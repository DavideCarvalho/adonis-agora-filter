`node ace agora:doctor` checks every installed `@adonis-agora` lib; `node ace filter:doctor` checks filter only.

```bash
node ace agora:doctor                  # every lib
node ace filter:doctor                 # filter only
node ace agora:doctor --json --strict  # in CI: one JSON object, fail on warnings too
node ace agora:doctor --no-boot        # the app does not boot: config checks without booting
```

| Flag | |
| --- | --- |
| `--lib=filter,durable` | only these libs |
| `--only=filter.manifest` | one check |
| `--deep` | also checks that reach a database, Redis or the network |
| `--json` | one JSON object on stdout |
| `--strict` | warnings fail too |
| `--verbose` | show skipped checks |
| `--no-boot` | do not boot the app (for when booting is what fails); runs the checks that only read config |

Exit code: `0` no error, `1` at least one error (or a warning with `--strict`), `2` the doctor could not run.

Add it to CI after the build:

```yaml title=".github/workflows/ci.yml"
- run: NODE_ENV=production node ace agora:doctor --json --strict
```

## Checks

| Id | What it checks | Status |
| --- | --- | --- |
| `filter.peers` | `@adonisjs/core` and Lucid are in the supported range | error |
| `filter.agora-siblings` | no 0.x and 1.x `@adonis-agora` libs mixed | warn |
| `filter.registered` | every installed Agora lib with checks has its provider registered | warn |
| `filter.manifest` | the `filters` manifest of `config/filter.ts` loads; the generated clients match it (none out of date, missing, or left over from a removed spec). Fix with `node ace make:filter-client` | error / warn / skip |

The doctor checks the clients in `codegen.output` of `config/filter.ts` (default
`app/generated/filters`, see [choosing the output directory](/docs/filter/codegen#choosing-the-output-directory)):

- clients there: they are compared with the manifest;
- `codegen.output` set but no clients there: warn, run `node ace make:filter-client`;
- no `codegen.output` and clients generated elsewhere with `--output`: the doctor finds them by
  their `// Code generated by @adonis-agora/filter` banner, compares them, and warns you to set
  `codegen.output` to that directory;
- no generated clients anywhere (you don't use codegen): the comparison is reported as skipped,
  with the directory it looked in (shown with `--verbose` or `--json`).

Formatting your generated clients is fine. Each client's banner carries a
`// Content hash: sha256:…` line, the hash of what `make:filter-client` emitted. Formatters
(prettier, biome, eslint `--fix`) leave line comments alone, so `filter.manifest` compares that
hash with a fresh generation instead of comparing code. A client is out of date only when the
manifest (or the generator) would now emit something different. Clients generated before the hash
existed are compared with quotes, semicolons, commas, whitespace, quoted keys and a union's leading
`|` ignored. Regenerate once to get the hash.
